1. Visão geral do fluxo

O worker externo simula compras, chama a API de análise de fraude (HBOS + XGBoost) e grava o resultado no Postgres. O Enterprise Hub só lê essas tabelas — não executa a simulação.

1
Worker monta a transação Payload com CPF, cartão, valor, estabelecimento, data/hora, limite, etc.
2
Chama a API de análise API avalia com HBOS (anomalia) e, quando aplicável, XGBoost (score de fraude).
3
Persiste no banco Grava em anfdatdados_analise_transacional_log_transacao: request, response e status final.
4
Você acompanha Via SQL no Postgres ou pela aba Resultados do Enterprise Hub (gráfico pizza + detalhe).
Tabela-chave: anfdatdados_analise_transacional_log_transacao — é nela que fica o que foi enviado, o que voltou e se foi aprovado.

2. Onde olhar (rápido)

O que enviamos?
Coluna des_request (JSON) — ou painel esquerdo no detalhe da transação no Hub.
O que a API retornou?
Coluna des_response (JSON com hbos e xgboost) — ou painéis de score no detalhe.
Foi aprovado?
Coluna des_status: approve deny challenge
Qual CPF / ID?
num_cpf e dados_analise_transacional_modelo (id da linha).
XGBoost não rodou?
Olhe des_response → xgboost.reason (ex.: skip por zona de challenge / features).

3. Tabela principal do teste assistido

anfdatdados_analise_transacional_log_transacao

Coluna O que é Para que serve no acompanhamento
dados_analise_transacional_modelo Identificador da linha Ordenar / referenciar a simulação (aparece como ID no Hub)
num_cpf CPF do portador Filtrar simulações de um cliente
des_request JSON enviado à API Ver exatamente o payload da simulação
des_response JSON retornado pela API Ver scores HBOS/XGBoost e sinais
des_status approve | deny | challenge Decisão final da análise
Se esta tabela estiver vazia (0 linhas), o worker ainda não gravou simulações — o dashboard de Resultados ficará zerado mesmo com o treino HBOS avançado.

4. Status: approve / deny / challenge

Valores gravados no banco (inglês). Na UI do Hub aparecem em português.

Banco (des_status) UI Significado
approve Aprovado Transação liberada — baixo risco segundo o modelo.
deny Negado Alto risco — transação recusada.
challenge Challenge Zona intermediária — tipicamente revisão / decisão assistida.

5. Request e Response (estrutura esperada)

5.1 O que enviamos — des_request

{
  "cpf": "00000000000",
  "numero_cartao": "************1234",
  "bandeira_cartao": "visa",
  "emissora_cartao": "...",
  "tipo_cartao": "Crédito",
  "produto": "...",
  "valor_compra": 199.90,
  "numero_parcelas": 1,
  "cnpj_estabelecimento": "00.000.000/0001-00",
  "ramo_atividade": "...",
  "data_compra": "2026-07-20",
  "hora_compra": "14:32:00",
  "percentual_limite_usado": 35,
  "tipo_limite": "Rotativo"
}

5.2 O que retornou — des_response

{
  "hbos": {
    "executed": true,
    "score": 0.1234,
    "signals": ["valor_sobre_media_cpf", "flag_horario_incomum"]
  },
  "xgboost": {
    "executed": false,
    "score_fraude": 0.42,
    "reason": "motivo do skip (quando não executou)"
  }
}

HBOS

Score de anomalia de 0 a 1 + lista de signals. Quanto maior o score, maior o desvio em relação ao perfil do CPF.

XGBoost

Probabilidade de fraude. Pode vir com executed: false e um reason explicando o skip.

6. Outras tabelas úteis

Nem todas entram no gráfico de Resultados, mas ajudam a entender o pipeline completo.

Tabela Papel Quando olhar
anfdatdados_analise_transacional_log_transacao Log do teste assistido (request / response / status) Sempre — acompanhamento da simulação
anfdatdados_log_analise_transacional_modelo Log alternativo da API (body, body_response, decision, score) Se o worker de produção gravar aqui além (ou em vez) do log acima
anfdmtdados_modelos_transacoes Fila de CPFs para treino (flg_processado) Progresso do worker de treino HBOS
anfdatdados_analise_transacional_modelo Modelos HBOS salvos (serializados) Quantos modelos já foram treinados
anfdatdados_analise_transacional_sem_transacao CPFs em triagem (histórico insuficiente) Por que um CPF não gerou modelo
anfdatdados_analise_transacional_consolidado Features agregadas do perfil Input histórico do treino/análise (contexto)

7. SQLs de monitoramento

Copie e rode no Postgres (DB usado pelo Hub).

Distribuição do teste assistido

SELECT des_status, COUNT(*) AS qtd
FROM anfdatdados_analise_transacional_log_transacao
GROUP BY des_status
ORDER BY qtd DESC;

Últimas simulações (enviado + retorno + status)

SELECT
  dados_analise_transacional_modelo AS id,
  num_cpf,
  des_status,
  des_request,
  des_response
FROM anfdatdados_analise_transacional_log_transacao
ORDER BY dados_analise_transacional_modelo DESC
LIMIT 50;

Buscar por CPF

SELECT *
FROM anfdatdados_analise_transacional_log_transacao
WHERE num_cpf = '00000000000';

Extrair scores do JSON de resposta

SELECT
  num_cpf,
  des_status,
  des_response::json -> 'hbos' ->> 'score'          AS hbos_score,
  des_response::json -> 'xgboost' ->> 'score_fraude' AS xgb_score,
  des_response::json -> 'xgboost' ->> 'reason'       AS xgb_reason
FROM anfdatdados_analise_transacional_log_transacao
ORDER BY dados_analise_transacional_modelo DESC
LIMIT 20;

Só os negados (para investigar)

SELECT num_cpf, des_request, des_response
FROM anfdatdados_analise_transacional_log_transacao
WHERE des_status = 'deny'
ORDER BY dados_analise_transacional_modelo DESC
LIMIT 30;

Progresso do treino HBOS (contexto)

SELECT
  (SELECT COUNT(*) FROM anfdmtdados_modelos_transacoes) AS fila_total,
  (SELECT COUNT(*) FROM anfdmtdados_modelos_transacoes WHERE flg_processado = false) AS fila_pendente,
  (SELECT COUNT(*) FROM anfdatdados_analise_transacional_modelo) AS modelos_salvos,
  (SELECT COUNT(*) FROM anfdatdados_analise_transacional_sem_transacao) AS triagem,
  (SELECT COUNT(*) FROM anfdatdados_analise_transacional_log_transacao) AS sims_gravadas;

Log alternativo da API (se houver dados)

SELECT id_log, dta_cadastro, cpf, decision, score, body, body_response
FROM anfdatdados_log_analise_transacional_modelo
ORDER BY id_log DESC
LIMIT 50;

8. Pelo dashboard Enterprise Hub

  1. Abra o Hub (app Electron ou npm run web-server).
  2. Vá na aba Resultados (teste assistido).
  3. O gráfico pizza mostra a distribuição Aprovado Negado Challenge.
  4. Clique em um status na legenda/fatia para listar as transações.
  5. Abra um item: coluna esquerda = request; direita = scores HBOS/XGBoost; badge = status final.
Endpoints HTTP (modo web): GET /api/assisted-test-data · GET /api/transactions-by-status?status=approve|deny|challenge

9. Checklist operacional

  1. Worker de simulação está rodando?
  2. SELECT COUNT(*) FROM anfdatdados_analise_transacional_log_transacao; — o número sobe?
  3. Distribuição de status faz sentido (GROUP BY des_status)?
  4. Abra 1–2 linhas e confira se des_request e des_response estão JSON válido.
  5. Para um deny, confira score HBOS/sinais e se o XGBoost rodou.
  6. Se a contagem não sobe: o worker pode estar falhando antes do INSERT, ou gravando em outra tabela/ambiente.
